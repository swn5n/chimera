# Chimera

Personal app: "SheepIt for agents." Split the task, not the model. Each step runs whole on one node with a model (or a Head/tool) that fits. General-purpose, not Blender-specific (Blender is just one thing to test with).

Current version: **0.8.0** (Nov 1, 2026: worker routing, repairs, the scene check and the look; 0.7.0 was Oct 29, Hydra 1.0, released Oct 30 with the Head maker merged in; 0.6.1 was Oct 25, 0.6.0 Oct 24). All computers on the pool must run 0.6.1 or newer: from 0.6.1 the computer running a Head reads its options, and the hub honours `not_here`. A 0.6.0 worker runs such Heads on their defaults, and the hub says so in the reply. Update the hub host and the Head computers first. Only put `hydra:1.0` on computers running 0.7.0 or newer: older builds (and an older hub) treat it as an ordinary chat model. Not enforced in code: `hubProto` (app/hub.go) is still 1, so a 0.5 device can still join. To bump the version, change `const Version` in app/main.go (build.sh fills in Info.plist) plus the README.md title.

- End-to-end tests: `cd app && go build -o <tmp>/chimera .`, then from `tests/plugin-network/`: `python3 run_it.py <tmp>/chimera <tmp>/chimera-it` and `python3 heads_text_test.py <tmp>/chimera <tmp>/chimera-ht`. Use a darwin build, never `dist/linux/chimera`. On macOS, copy a rebuilt binary to a fresh path (or `rm` first): overwriting a signed binary in place gets it killed at launch (exit 137). Each takes about a minute (give Bash a long timeout; macOS has no `timeout` command).
- Test instances aren't fully isolated from the real pool: they bind the real UDP discovery port 7479, and `staleHubWatch`/`rejoinSomewhere` ignore `CHIMERA_NO_AUTOPOOL`, so a leftover test worker whose hub dies can join a real open pool on the LAN. Don't run them while (re)starting the Studio's real Chimera, and kill leftovers after an interrupted run. To join a test instance to the real pool as an asker only, set `auto_help` off or it lends itself. A second instance on the same `--ui-port` quits with "already running", so check which process holds the port (`lsof -iTCP:<port> -sTCP:LISTEN`) and kill by that PID: a `./chimera` command line doesn't match a pattern on its folder.

## Ports
- 7470 local UI (127.0.0.1; falls back to 7471-7474, `--ui-port`)
- 7480 hub (host only, all interfaces, `--hub-port`)
- 7479 UDP discovery (needs SO_BROADCAST; on macOS also the Local Network permission)

- Devices only dial out. Heartbeat 3 s; long-poll `/v1/work`.

## Decided (from the user; don't relitigate)
- Lending is a manual Connected / Disconnected toggle (like SheepIt), no idle detection. Light use of the computer is fine while connected.
- Disconnecting mid-job offers "finish current step, then disconnect" and "stop now".
- Ollama must be running before a device can connect.
- General-purpose, not Blender-specific.
- Dark grey design using the chimera icon and logos.
- Download models from inside Chimera, picked to fit each device with headroom. Work out each device's context limits, model limits and installed tools.
- If nobody is lending, a chat runs on the user's own best model.
- Show what each device is best for and which waiting work it could help with.
- Long tasks get a system prompt telling each node it is one small piece of a larger project; the prompt varies by task type.
- Internal library of known-working mechanics, reused instead of calling models ("distilling ourselves"). 5-star rating after replies; 4-5 stars asks what worked; the network's largest GPU turns that into a central library entry. When spare compute is idle for a set time, test library entries for spam or mistakes; errors flag for the host.
- Web app, installable so it shows in the macOS Dock with the Chimera icon.
- Testing credits: everyone gets 1,000,000 starter credits; set back to 100 after testing. Going negative must actually limit you.
- Devices on the same Wi-Fi connect automatically (no code/IP sharing). A user's own devices auto-connect to help with their long tasks.
- Looping mode = iterate until done: parse (planner), sub-agents (workers), piece (combine), review, repeat.
- Open pool: anyone on any network can auto-join and contribute; credits (not codes) prevent freeloading. **Privacy is explicitly NOT a goal for now** ("ideally privacy is something we can do but for now lets just get it working"). Don't add encryption or privacy work unprompted.
- Tools are called **Heads** in the UI/docs (code, `plugin.json` and API keep `plugin`). A user's custom tool (e.g. the Perspective Blender plugin for studio shadows) should be called instead of an AI model when it does the job better. Rate Heads with the 5 stars. A Head owner whose tool gets called earns extra credits for bridging AI with deterministic techniques. Keep it open for future tools. Integrate other local AI models (mainly 3D mesh and picture generation) from the Nvidia PC.
- Heads run off the computer that hosts them and just return results to the asker via the chat. The asker's own computer (its GPU) is used for Head work only when the Head is its own (installed there). Applies to all future Heads.

## Architecture notes
- Routing: `need_caps` / `need_ctx` / `prefer`; context buckets 8K/32K/64K/128K; local fallback with a note. Stalled/offline steps retried elsewhere (3 tries). Worker steps (Oct 31, `hub_workers.go`) use `prefer: "worker"` with the task's id: the hub learns the seconds a step takes per computer and model (`worker_secs` in `hub.json`, only from worker steps) and picks the lowest cost, not the biggest model. Cost = those seconds, or a guess from speed plus `workerUnproven` 600 for an untimed model; load time if not loaded; `workerSmallCost` 1000 under 8B; 45 s per step that computer already did for the task, up to 2 (`workerSpreadMax`). An empty or cut-off reply is learned as 300 s worse. A free computer at least 45 s better that isn't polling gets up to `helperWait` (`workerAboutToAskLocked`). Chats, the combine and a one-step plan's only step keep the old scoring (`workerPrefer`). A free slow computer still takes a step ahead of a busy fast one, on purpose so far (`docs/joint-task-oct31.md`, Routing). `pickLocalModel` uses the same guess.
- Long tasks (Hydra, `hydra.go`): the helper model (else the biggest model) plans 2-7 JSON steps, parallel workers (max 4) with per-kind prompts, verified library entries reused, biggest model combines. Only in looping mode ("Keep going until done", off by default) does it then review (`{done, score, critique}`, the helper else the biggest model) and re-plan, up to 6 passes (`hydraMaxRounds`). `score` is unused, and a non-integer score fails the parse and ends the loop as if done. A later round that errors keeps the best result so far (`keepRound`, with a note) instead of failing the task.
- Repairs, later rounds and the best round (Oct 31, `hydra_mend.go`, `execute` in `hydra.go`; why: `docs/joint-task-oct31.md`). A script that fails the check gets up to `hydraMends` (8) repairs inside its round (`mendScript`, phase `mending`): the biggest model gets only the script and the error (`hydraMendPrompt`) and replies with FIND/REPLACE edits (`editFormat`); `applyEdits` puts them in the script, `withScript` puts the script back in its code block by position (`pickBlock`), and it's checked again. Two tries in a row that get nowhere end it (worse, which is taken back, `Undone`; nothing that applies; the same error on the same line). `applyEdits` matches without trailing spaces, then without indents (`reindented`), since wrong indents were most misses. An edit matching several places changes them all unless it only adds lines (`keepsAll`). `parseEdits` drops an edit that adds a code fence, one that ran into the next, and repeats. A reply that writes the script out counts if it's about as long with mostly the same lines (`writtenOut`).
